# Пакет `surv` — игра «Выживание» по модулям

Игра выросла из одного файла `Surv.py` (~20 000 строк) и держит сотни общих
глобальных переменных: мир, игрока, камеру, инвентарь, открытые меню, шрифты.
Полный рефакторинг «каждый модуль со своими переменными» потребовал бы
переписать тысячи обращений, поэтому применяется схема **общего пространства
имён**: части игры лежат в отдельных файлах, но выполняются в глобалах одного
модуля `surv.runtime`. Для кода это ровно тот же единый модуль, что и раньше,
а для читателя — файлы по темам.

## Запуск

```
python Surv.py        # привычная команда, тонкая обёртка над surv.runtime
python -m surv        # то же самое через пакет
```

Обе точки входа запускают `surv.runtime.main()`.

## Устройство

```
Surv.py              совместимый фасад: import Surv видит имена игры,
                     запись в них попадает в surv.runtime (не в копию)
surv/
  __init__.py        описание пакета, ничего не запускает
  __main__.py        python -m surv
  config.py          настройки, палитра, таблицы данных (только данные)
  netcode.py         _UdpNet: надёжный слой поверх UDP
  visual.py          визуальный слой: палитра, панели, тени, свечения, текст
  runtime.py         загрузчик: config + visual + части -> общее пространство имён
  parts/             части игры, выполняются по порядку
```

## Визуальный слой

`surv/visual.py` — единственное место, где описан внешний вид интерфейса:
палитра (`PAL_*`) и примитивы с префиксом `vis_*` (панели, тени, свечения,
виньетка, зерно, текст с обводкой и градиентом, полоски, точки).  Модуль
самодостаточен: импортирует только pygame/numpy и не знает про мир игры.
`runtime.py` подмешивает его `__all__` в общее пространство имён, поэтому
части вызывают `vis_panel(...)` так же, как обычные функции.

Правила:

* Всё рисуется процедурно, внешних картинок нет.
* Тяжёлые поверхности (панели, тени, фон меню, небо, виньетка) считаются
  один раз и кэшируются по размеру/цвету — кадр не должен пересобирать их.
* Новые элементы интерфейса собираются из `vis_*`, а не из «голых»
  `pygame.draw.rect`: так меню, HUD и панели остаются в одном стиле.
* Цвета интерфейса в `config.py` (`BUTTON_*`, `TEXT_*`, `PANEL_BG*`)
  согласованы с палитрой `visual.py`; менять их лучше парой.

## Правила для правок

* Части **не** импортируют друг друга и не имеют своих `import` — они видят
  глобалы `surv.runtime`.
* Порядок в `_RT_PARTS` (`surv/runtime.py`) повторяет порядок исходного файла.
  Переставлять части нельзя: объявления классов и модульные значения
  выполняются сверху вниз.
* Новая часть добавляется файлом в `parts/` и строкой в `_RT_PARTS`;
  имя начинается с номера, чтобы порядок был виден в проводнике.
* Константы и таблицы данных кладём в `surv/config.py` — его имена
  подмешиваются в `surv.runtime` до выполнения частей.
* Самодостаточный код без игровых глобалов (как `_UdpNet`) лучше выносить
  в обычный модуль рядом с `config.py`.

## Совместимость

`Surv.py` подменяет свой класс модуля на фасад с `__getattr__`/`__setattr__`,
поэтому старые скрипты и тесты (`import Surv`, `Surv.game_world = ...`,
`from Surv import main`) продолжают работать и пишут в живой мир, а не в
копию.
